# INT-001: Provider Registry Snapshot in AppState

## Pattern reference

- Pattern: PAT-001 Declarative Provider Registry with Inventory State
- Source repository: block/goose
- Related RD: RD-001

## Reason

ACC needs a unified way to discover, configure, and present providers in the UI. Today provider state is scattered. A registry snapshot would let the UI render a provider catalog without instantiating clients.

## Proposed ACC usage

- Add a `ProviderRegistry` service under `ai_command_center/core`.
- Publish `provider.discovered`, `provider.configured`, `provider.changed` on EventBus.
- `AppState` holds a `ProviderRegistrySnapshot` projection.
- UI reads `AppState` and sends `provider.select` commands.

## Files / modules affected

- `ai_command_center/core/state/app_state.py`
- `ai_command_center/core/settings/settings_service.py`
- `ai_command_center/core/ai/` provider modules
- New `ai_command_center/core/ai/provider_registry.py`

## Estimated effort

Medium

## Dependencies

- EventBus topic definitions
- AppState projection framework
- Settings schema for provider config keys

## Risk assessment

- Low risk if introduced as additive service.
- Must not bypass existing `OllamaService` contract.

## Constitutional compliance

- Does this violate the Constitution? No.
- Does this weaken Execution Authority? No.
- Does this weaken State Authority? No.
- Does this duplicate existing systems? Partially overlaps provider adapters; resolve by making adapters consumers of the registry.
- Is there a simpler solution? Yes, but registry improves scalability.
