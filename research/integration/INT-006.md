# INT-006: Settings migration and precedence layer

## Pattern reference

- **Pattern:** PAT-005 — Layered configuration with precedence, migrations, and secret fallback
- **Source repository:** block/goose
- **Related RD:** RD-001

## Reason

ACC already has `SettingsSnapshot` and a `migration_manager.py` placeholder. Goose demonstrates how to load layered config files, apply environment overrides, and run schema migrations before the app reads settings.

## Proposed ACC usage

1. Extend `SettingsService` to load system-wide, additional-user, and user-default config files in order.
2. Apply `APPDATA`/`GOOSE_*` environment overrides as the top precedence.
3. Implement `MigrationManager` with versioned migrations that rewrite legacy keys to new schema.
4. Add keyring/file fallback for secrets in `SettingsRepository`.
5. Keep `SettingsSnapshot` as the immutable snapshot injected into services.

## Files / modules affected

- `ai_command_center/core/settings/settings_service.py`
- `ai_command_center/core/settings/migration_manager.py`
- `ai_command_center/core/settings/settings_repository.py`
- `ai_command_center/core/settings/settings_schema.py`
- `ai_command_center/core/state/app_state.py` (propagate `settings.updated`)

## Estimated effort

Medium — 3-5 days.

## Dependencies

- Existing `SettingsSnapshot` dataclass.
- `keyring` package or encrypted file fallback.
- `pydantic`/`dataclasses` validation already in `settings_schema.py`.

## Risk assessment

- Low: improves robustness of existing settings layer.
- Medium: migrations must be carefully ordered and tested.
