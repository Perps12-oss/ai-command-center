# INT-003: Session-scoped service creation locks and LRU cache

## Pattern reference

- **Pattern:** PAT-003 — Per-session creation lock with bounded LRU service cache
- **Source repository:** block/goose
- **Related RD:** RD-001

## Reason

ACC's headless core creates 19 services on startup, but per-session objects (agents, MCP runtimes) can be constructed lazily. Goose's `AgentManager` shows how to avoid duplicate initialization and bound memory.

## Proposed ACC usage

1. In `ServiceManager` or a new `SessionServiceManager`, maintain an `LRU` cache of session-scoped service bundles keyed by session ID.
2. Maintain a dict of `asyncio.Lock` per session to serialize creation.
3. Re-check the cache inside the lock before constructing.
4. On eviction, call `stop`/`unload` on the bundle and prune the lock when no waiter holds it.

## Files / modules affected

- `ai_command_center/core/service_factory.py`
- `ai_command_center/services/base.py` (`stop`/`unload` lifecycle)
- `ai_command_center/core/state/app_state.py` (track active sessions count)
- `ai_command_center/repositories/` (session-scoped cleanup)

## Estimated effort

Small — 2-3 days.

## Dependencies

- Existing `BaseService` lifecycle states (`STOPPED`, `STARTING`, `READY`, etc.).
- `cachetools` or similar LRU implementation.

## Risk assessment

- Low: additive; improves concurrency and memory.
- Medium: cleanup on eviction must be robust to avoid resource leaks.
