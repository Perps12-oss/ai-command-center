# PAT-005: SQLite Session Storage with Schema Migrations

## Problem

Session state must persist across restarts, support schema evolution, and handle concurrent writers safely.

## Solution

Goose stores sessions in SQLite via sqlx. It uses WAL mode, `BEGIN IMMEDIATE` migrations, a `CURRENT_SCHEMA_VERSION` constant, lazy pool initialization, and a builder-based `SessionUpdateBuilder` for typed partial updates.

## Benefits

- Reliable persistence.
- Schema migration path.
- Concurrent-first-run safety.

## Used by

- block/goose (`crates/goose/src/session/session_manager.rs`)

## ACC usage

ACC already uses SQLite through repositories. This pattern is a reference, not a new subsystem. If `ConversationRepository` needs migration support, this pattern can inform it.

## Compatibility

- Overlaps existing `ai_command_center/repositories/` pattern.
- No immediate need.

## Priority

Low

## Risks

- Replicating repository layer.
- Rust/sqlx details not directly portable.

## Status

Hold. Re-evaluate when repository migration requirements arise.
